Open Commerce — internal reference

Who lands where, and what happens next

Three people touch this project today — a seller publishing a component, a human's AI agent buying one, and a builder wiring up their own agent host. Each crosses a different set of pages, hosted on three different services, with real API calls and real money in between. This maps what's actually live versus what's still a gap, not the intended design.

What this map makes visible

  • The landing page has no live inbound path. It's fully built and deployed, but nothing else in the project links to it yet — every visit today has to be a direct link someone was handed.
  • Human checkout doesn't exist. A person who lands on a storefront listing page reads the same embed an agent would, but there's no "buy" button wired up for them — only agents can actually complete a purchase today.
  • The registry submission form has a UI now, but still isn't public. It runs locally (localhost:3002) with a real form, a working SSRF guard, and real schema validation — a Render service for it is declared in render.yaml but has never actually been deployed (confirmed live: x-render-routing: no-server), so nothing points a real seller at it yet.
  • Multi-tenant auth is live, but only exercised by one seller. Signup, login, and per-seller data are real and working — but the only account that exists today is Priya's, migrated into the new system rather than created through the live signup form. The path is unverified end-to-end with a second, genuinely new seller.
  • Two agent discovery paths exist independently. The registry (MCP) and the open-web embed (schema.org JSON-LD) both work today and neither depends on the other — an agent doesn't need to know about the registry at all if it just reads a page.
